 PHASE 2 - WORK SPLIT & GITHUB PUSH PLAN  (4 MEMBERS)
 Project: Direct-Mapped Cache Controller -> 2-way Set-Associative, Write-Back
===============================================================================

Phase 2 completes the project. It extends the Phase 1 direct-mapped read-only
cache into a 2-way set-associative, WRITE-BACK cache (reads + writes, LRU
replacement, dirty bit), and adds design-space analysis (parameter sweep) and
logic synthesis.

These files are pushed to the SAME repository that already holds Phase 1, so
the two phases together form the complete project.

Each of the 4 members owns distinct files (so GitHub shows each person's
contribution) and has about 5 commits.
Suggested merge order: M1 -> M2 -> M3 -> M4.

===============================================================================
 HOW TO VERIFY BEFORE PUSHING
===============================================================================
  make model    # Python reference-model self-test  -> "self-test: OK"
  make sweep    # parameter sweep (needs no HDL tools)
  make run      # compile RTL + run testbench on all traces (needs iverilog)
  make synth    # synthesize the cache (needs yosys)

 Key result to show: on the "conflict" trace the direct-mapped cache gets 0%
 hits while the 2-way cache gets 99.22% - the set-associative win. RTL hit
 ratios and writeback counts match the Python model exactly. Synthesis reports
 ~25,233 cells and ~9,828 flip-flops for the cache.
